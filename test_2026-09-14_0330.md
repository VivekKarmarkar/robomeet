# RoboMeet: where we are, and the next test

Written 2026-09-14 03:30 EDT, after live test 3 (Vivek's own meeting). Pick up here.

## Where we are starting from

The test we were aiming for works: Vivek sends a Google Meet link, the robot knocks, gets admitted, is live before anyone speaks, greets in its own words, holds a natural conversation, introduces itself from the facts it was given, and answers in about 1.2 to 1.7 seconds after the last word. Vivek's words: "went extremely well this time", "acceptable latency", "it felt free and it responded so nicely, exactly how GPT Live usually responds".

## Resolved since that test (all in code, tests 16/16, robot idle)

1. **Voice** pinned to `marin` (the voice Vivek tested and liked in the playground). Every session, same voice. `ROBO_VOICE` overrides.
2. **Freeze during delegation** fixed: the moment a request is handed to the coding agent the robot says so and keeps talking. Verified with a job held for 25 s: three hellos and "are you still there" answered meanwhile, result reported after.
3. **Full context at launch**: the briefing covers what it is; RoboMeet (in house, on Vivek's laptop) launched it and links it to a coding session; gpt-live-1 and how it takes turns; gpt-5.6-sol, the backend reasoning model, and how delegation works; the tools; the coding session (agent and session name as launch parameters, over the RoboMeet MCP server, its directory and project, it reads the transcript); that it can keep talking during a request; camera and screen; why it is here (`--purpose`); extra context from the launching session (`--brief`); a recap on a rejoin; then "be yourself". The `/robomeet` skill tells the launching session to fill `--purpose` and `--brief` every time. Verified in a meeting.
4. **Pictures and PDFs on the shared screen**: a slide body `image:/slides/<file>.png` shows a picture; `present_pdf` (MCP tool) or `node bin/present-pdf.mjs <file.pdf>` turns every page into a slide. The slide canvas is redrawn continuously, so frames actually reach Meet (before, Meet never received a first frame).
5. **Rejoin**: if Meet shows "Switch here" for the robot's own stale session, the worker uses "Join here too" and never "Switch here". Rejoins are still to be avoided mid-call: a new session has no memory and the robot's Chrome window pops up on Vivek's laptop.
6. **Single-hop voice path** is the default (GPT Live session inside the Meet tab); jitter and keep-alive fixes; `openai-docs` MCP registered at user scope.

Details and Vivek's exact words: `errors_and_observations.md`, and the context anchors.

## The next test (one call, no rejoins)

Launch from a Claude Code session with `/robomeet <link>` (Vivek creates the Meet from his own account and sends the link; the skill passes `--purpose` and `--brief`). Then, in order:

1. Admit the robot. Expect: it greets first, in its own words, within about 3 s of admission.
2. Say hello. Expect: an immediate short reply, about 1.2 to 1.7 s after the last word.
3. Ask who it is and how it got here. Expect: its own words, correct facts (Vivek Bot, RoboMeet, connected to the Claude Code session named meetingproject, launch parameters), no scripted sentence.
4. Ask it to take a note ("note that the deadline is Friday"). Expect: it confirms only after the note is saved; check with `node bin/tool.mjs notes '{}'`.
5. Ask it to have the coding agent do something small ("ask the coding agent how many test files the project has"). Expect: it says it has handed it over, keeps talking if spoken to, and reports the answer when the session replies.
6. Ask it to present a PDF (Vivek names a PDF on the laptop, or the session uses `/tmp/claude-1000/test-deck.pdf`). Expect: pages on the shared screen, visible to Vivek, no rejoin.
7. Say bye and end the call. Expect: voice stops within 30 s of the robot being alone; `node bin/command.mjs status` shows voice idle.

Listen for: the same voice throughout; no silence longer than a normal pause; no scripted sentences.

If something breaks mid-call: say so in the terminal and stop. Do not rejoin, do not open windows, do not publish pages.
